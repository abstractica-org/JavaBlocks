**In short:** `ThreadBlock.stop()` used to hang forever unless the worker happened to be waiting on a buffer. That covers the library's own timer pattern. It now returns for every kind of input. (`ThreadBlock` is the only block that owns a thread; `stop()` is how a host shuts it down.)

**What happened, in plain words:**

- **The fix, kept inside one class.** `stop()` no longer holds the block's lock while it waits for the worker to finish; holding it was what caused the deadlock. The worker now finishes the item it holds, delivers it, then exits. When the worker dies for any reason, the block now says "not running".
